## Замеры

Подробности: load-results.json, ui-performance.json, browser-results.json. Замеры сделаны на loopback с демонстрационными данными, без реального Redis. 50 запросов одновременно к спискам/аналитике: 0 ошибок, p50 1228 мс, p95 1340 мс, максимум 1352 мс. 10 одновременно формируемых отчётов разных форматов/колонок: 0 ошибок, p95 653 мс. Обычные действия UI: комментарий 221 мс, переход 480 мс, preview отчёта 320 мс.

Это проверка 50 конкурентных запросов с действующей сессией, а не длительная модель 50 независимых пользователей. Требование ≤1 секунды при такой нагрузке не подтверждено. Нужен отдельный прогон Linux Compose с Redis, целевыми объёмами и профилем пользователей. Скрипты оставлены для воспроизведения.

Дополнительный эксперимент с двумя native Windows Uvicorn workers ухудшил хвост задержек: p95 около 30 секунд, хотя ошибок HTTP не было. Результат сохранён в load-results-two-workers.json; эта конфигурация не принята. Итоговый Compose и локальный API оставлены с одним worker. Автоматически переносить результаты Windows multiprocessing на Linux нельзя.

## Definition of Done

Дополнительный прогон после продолжения работ: `scripts/load_test.py` создаёт 50 отдельных сессий Keycloak через Authorization Code + PKCE, выполняет 5 синхронных раундов (250 запросов), затем 10 одновременных отчётов и завершает тестовые сессии. Токены не сохраняются. Результат в load-sessions-results.json: 0 ошибок, p50 479 мс, p95 1217 мс; отчёты p95 582 мс. До оптимизации медиана была 591 мс, но общий p95 нового прогона выше из-за первого раунда. Удалены лишние запросы к БД при недоступном кэше, три агрегата Dashboard объединены в один SQL round trip. Требование ≤1 с по-прежнему не объявляется закрытым.

Функциональные пункты 6–28 реализованы: авторизация/роли, Dashboard, CRUD ВУЗов/программ/продуктов, workflow/переходы, комментарии, файлы, Excel, фильтры, XLSX/PDF, Swagger, две mock-интеграции, seed, README, документация и тесты. Критических TODO/заглушек в бизнес-операциях нет. Интерфейсы Protocol и mock-адаптеры — предусмотренные точки расширения.

Пункты 1–5, относящиеся к `docker compose up --build`, нельзя отметить пройденными: конфигурация проверена, но Docker Engine недоступен. PostgreSQL, Keycloak, backend и frontend запущены и проверены отдельными локальными процессами. CI workflow подготовлен для сборки и smoke-проверки настоящего Compose на Ubuntu, но его внешнее выполнение здесь не заявляется.
